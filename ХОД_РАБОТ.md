## Этап 5 — уведомления, личные правки, фон (Android)
- **Уведомления:** `flutter_local_notifications` (+ `timezone`). Что и когда показывать, считает `domain/notification_plan.dart`; ставит `notifications/notification_gateway.dart`
  (`zonedSchedule`, точные будильники через `USE_EXACT_ALARM`, каналы «Пары» / «Домашка» / «Обновления расписания», своя иконка `ic_notification`).
  Пересчёт — `app_outputs.dart` (`replanNotifications`) после любого изменения расписания, ДЗ, правок, настроек и при возврате в приложение.
  Разрешение (Android 13+) спрашивается один раз при первом запуске; в «Настройках» — время напоминания (выкл / 5 / 10 / 15 / 30 мин), вечернее ДЗ, кнопка «Разрешить уведомления».
- **Личные правки** (таблица `overrides`): долгое нажатие на пару → «Добавить ДЗ» / «Изменить на этот день» (аудитория, преподаватель, заметка) / «Отменить пару» /
  «Вернуть как было»; «Мои правки» на каждом дне — список правок и «Добавить свою пару». Правки учитываются в «Сегодня», виджетах и уведомлениях
  (`features/overrides/day_edits.dart`, `data/repositories/overrides_repository.dart`).
- **Фон:** `workmanager`, раз в ~6 ч (`background/background_sync.dart`): синхронизация → «Расписание обновилось» → снимок виджетов → план уведомлений.
  Задача работает в отдельном движке Flutter, поэтому данные виджетам передаёт пакет **`home_widget`** (он регистрируется во всех движках);
  собственный канал `raspisanie/widget` убран, Kotlin читает снимок из `HomeWidgetPreferences` (ключ `snapshot`).
- **Проверено на эмуляторе (Android 15):** окно разрешения; уведомление «ЧТК и этика → 2-15 · Ахмадова М.П. · через 10 мин» ровно в 14:30 при пустом приложении;
  отмена пары убирает её с экрана и из снимка виджетов; фоновая задача (принудительно, с переводом часов) выполняется с `Worker result SUCCESS` и обновляет снимок и виджет
  при закрытом приложении; релизный APK запускается и ставит 24 будильника.
- **Как принудительно запустить фон в эмуляторе:** `adb shell cmd jobscheduler run -f -n androidx.work.systemjobscheduler ru.raspisanie.raspisanie <ID>`
  (ID — из `dumpsys jobscheduler`, у нас обычно 1, 2, …); WorkManager не запускает периодическую задачу раньше срока, поэтому сначала сдвиньте часы эмулятора
  на 6+ часов вперёд (`adb root; adb shell date MMDDhhmmYYYY.ss`).
- **Не проверено:** реальные телефоны (экономия батареи Xiaomi/Huawei может убивать фон и будильники — нужен тест у владельца), сеть до настоящего сайта (адрес ещё не задан),
  тап по уведомлению (открывает приложение, без перехода на нужный день).
- **Известные ограничения:** на Android 12+ с Doze уведомления точные только при разрешённых «будильниках и напоминаниях» (`USE_EXACT_ALARM` выдаётся автоматически;
  если этого не будет в магазине приложений — перейти на `SCHEDULE_EXACT_ALARM` и запросить у пользователя).

  ближайшая граница) без Android-классов; `WidgetRenderer.kt` — RemoteViews; `WidgetUpdater.kt` — обновление + `AlarmManager.setWindow`

- **Отступление от спецификации:** обычные `RemoteViews`, а не Jetpack Glance: у Glance нет `Chronometer`, а обратный отсчёт должен тикать
  сам; плюс меньше риска со сборкой. Пакет `home_widget` не используется — свой канал (меньше зависимостей).
- **«+ ДЗ»:** ссылка `raspisanie://homework/new?subject=…` → `MainActivity.onNewIntent`/`getInitialLink` → канал `raspisanie/links` →
  `HomeShell._openLink` открывает вкладку «ДЗ» и окно «Новое ДЗ» с предметом.
- **Тесты:** Dart — `test/widget_bridge_test.dart`; Kotlin — `app/android/app/src/test/.../WidgetLogicTest.kt`
  (`cd app/android && ./gradlew testDebugUnitTest`).
- **Проверено на эмуляторе** (Pixel 6, Android 15, время выставлено на среду 7.10.2026 13:30 МСК): оба виджета добавляются из списка
  «Расписание → Сейчас / Далее, Сегодня»; 2×2 показывает «СЕЙЧАС · Техн. предп. · 2-05 · до конца 58:22» с тикающим отсчётом и значком «Л»;

  лаунчер просто не даёт его разместить (это поведение лаунчера, а не ошибка).

## Как запустить эмулятор и проверить виджеты (для следующего исполнителя)
Всё поставлено вручную в `/opt/homebrew/share/android-commandlinetools` (SDK 36, build-tools 36.0.0, platform-tools, NDK 28.2.13676358,
emulator 37.3.3, образ `system-images;android-35;google_apis;arm64-v8a`, AVD `pixel35` в `~/.android/avd`). Скачивание Gradle'ом/sdkmanager'ом
здесь очень медленное (~150 КБ/с на один поток), поэтому NDK, эмулятор и образ качались вручную параллельными `curl -r` кусками с проверкой sha1.
```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17 ANDROID_HOME=/opt/homebrew/share/android-commandlinetools PATH=/opt/homebrew/opt/openjdk@17/bin:$PATH
$ANDROID_HOME/emulator/emulator -avd pixel35 -no-window -no-audio -gpu swiftshader_indirect &   # без окна; скриншоты: adb exec-out screencap -p
cd app && flutter build apk --debug && $ANDROID_HOME/platform-tools/adb install -r build/app/outputs/flutter-apk/app-debug.apk
adb root && adb shell "date 100713302026.00"      # поставить время (МСК; часовой пояс уже Europe/Moscow)
```
Профиль можно задать без экранов выбора: положить `shared_prefs/FlutterSharedPreferences.xml` (`flutter.form`, `flutter.groupId`, `flutter.subgroup`, `flutter.pe`)
через `adb shell run-as ru.raspisanie.raspisanie`. Виджет на экран ставится перетаскиванием из списка виджетов (`adb shell input draganddrop`).
Kotlin-тесты: `cd app/android && ./gradlew :app:testDebugUnitTest` (14 тестов; без `:app:` Gradle запустит и тесты плагинов — у `image_picker` они падают из-за кириллицы в пути).

## Быстрая веб-версия и APK на сайте (2026-10-11)

**Почему веб-версия открывалась долго.** В первый раз браузер скачивает ≈4,7 МБ (рисовальный движок 2–3 МБ, код приложения 1 МБ, база данных ≈0,5 МБ, шрифты), причём файлы базы начинали грузиться только после запуска движка, а собственного кэша у приложения не было (встроенный кэш Flutter убрали: `flutter_service_worker.js` теперь пустая заглушка). Повторно файлы жили в браузерном кэше всего 10 минут (так отвечает GitHub Pages).

**Что сделано** (`app/web/`, `scripts/make_sw.py`):
- `sw.js` — собственный кэш приложения. Регистрируется из `index.html` после первого кадра (чтобы не мешать загрузке). После этого приложение открывается без сети и сразу. Расписание внутри приложения отдаётся из кэша и тихо обновляется; сервер группы и расписание из интернета идут мимо кэша. Отпечаток сборки считается по файлам приложения без расписания, поэтому обновление расписания не заставляет всех заново качать 5 МБ. `scripts/make_sw.py` подставляет в `sw.js` отпечаток и список файлов (вызывается из `build_web.sh`).
- `web/flutter_bootstrap.js` — свой шаблон без `serviceWorkerSettings` (иначе загрузчик Flutter заменил бы наш кэш на заглушку).
- `index.html`: файлы базы (`sqlite3.wasm`, `drift_worker.js`) скачиваются заранее, параллельно с движком; через 3,5 с загрузки появляется подсказка «первый запуск самый долгий… дальше сразу».
- Главная страница: у посетителей с iPhone, когда они доходят до раздела «Как установить», тихо подгружаются файлы веб-версии (`<link rel=prefetch>`, ≈3,6 МБ; не на Android и не при включённой «экономии трафика»).
- Измерения (медленный интернет 2 Мбит/с, Chrome): первый запуск 15,5 с (упирается в скорость), повторный 2,6 с без обращения к сети, без интернета открывается. Проверялось на тестовом сервере (`scratchpad/slow_server.py` + puppeteer-core), не на настоящем iPhone.
- Что ещё могло бы ускорить первый запуск (не делалось): хостинг со сжатием brotli (Cloudflare Pages: ≈−25% объёма), разбиение кода приложения на части.

**APK на сайте.** Кнопка «Скачать для Android» теперь ведёт на `raspisanie.apk` на самом сайте. `publish-schedule.yml` (шаг «APK на сайте») скачивает файл из последнего выпуска (Releases) и пишет `apk.json` (версия, размер для подписи под кнопкой); страница больше не обращается к github.com. После выпуска `build-apk.yml` сам запускает публикацию сайта (выпуск, созданный задачей, другие задачи не запускает). ## Уведомления в боевой сборке (2026-10-13)

Настоящая причина, почему не было ни окна с разрешением, ни напоминаний: в **release**-сборке пропадал значок уведомлений `drawable/ic_notification`. Сборка вырезает ресурсы, на которые нет ссылок в разметке и манифесте, а в коде значок указан только строкой `'ic_notification'`. Без значка `flutter_local_notifications` не запускается (ошибка глушилась в `catch`), поэтому не работали ни запрос разрешения, ни планирование напоминаний. В отладочной сборке всё работало, поэтому раньше это не нашли (изменения с «двумя вопросами» и кнопкой настроек из прошлого раздела остаются нужными).
- Исправление: `app/android/app/src/main/res/raw/keep.xml` (`tools:keep="@drawable/ic_notification"`).
- **Урок:** любой ресурс, который код находит по имени-строке (`getIdentifier`, `AndroidInitializationSettings('…')`), надо защищать в `keep.xml`. Проверять уведомления и виджеты нужно на **release**-APK, а не только на отладочной сборке.
- Проверено на эмуляторе на release-APK: с чистой установки появляется системное окно, после «Разрешить» в системе стоят запланированные напоминания (`ScheduledNotificationReceiver`). Выпуск с исправлением — после слова «выпускай».

## Исправление: файлы и фото от преподавателя (и старосты) не скачивались (2026-10-15)

Жалоба владельца: в приложении не скачать фото и файл от преподавателя, в веб-версии фото видно, а pptx не скачать и не посмотреть. Воспроизведено на эмуляторе (выпущенный APK v0.3.0, студент 1 БИ-25): нажатие давало «Не удалось скачать файл. Проверьте интернет и повторите».
**Причина 1 (главная, касалась и файлов старосты):** сервер отдаёт файл в base64 через `encode(..., 'base64')`, а Postgres вставляет в него перенос строки каждые 76 знаков; `base64Decode` в Dart такой текст не читает (FormatException). Скачивался только файл меньше ~57 байт. Тесты этого не ловили, потому что тестовый сервер отдавал base64 без переносов (теперь переносит как настоящий).
**Исправлено:** на сервере (миграция `fix_file_base64_newlines`: переносы убираются, это починило и уже выпущенный APK, и старую веб-версию без обновления) и в приложении (`shared_api.dart` убирает пробелы и переносы перед разбором).
**Причина 2:** роль `anon` обрывает любой запрос через 3 секунды; загрузка файла до 8 МБ иногда падала «canceling statement due to statement timeout». Миграция `file_functions_statement_timeout`: функциям `put_group_file`, `put_teacher_file`, `get_group_file` выдано 25 секунд (настройка внутри функции действует, проверено), столбец с файлами не сжимается повторно.
**Причина 3 (внешний вид):** имя файла приходило закодированным («%D0%A1%D0%BE…pptx»); теперь `cleanFileName` читает его как «Создание….pptx» при выборе, отправке и показе (`domain/attachment.dart`).
**Подсказка:** если на телефоне нет программы для .pptx/.docx/.xlsx/.pdf, сообщение советует, что поставить (Google Презентации, WPS Office).
**Проверено:** настоящий клиент (`SharedApi`) против настоящего сервера — 4 файла (10 Б, 230 КБ, 1,5 МБ, 8 МБ) отправлены от тестового преподавателя двум группам и скачаны студентами без искажений (15/15), чужая группа файл не получает; загрузка 2, 5 и 8 МБ — 12 из 12 удачных; в веб-версии в Chrome pptx скачивается; в эмуляторе фото открывается, pptx доходит до системы (на эмуляторе нет программы для pptx). Тестовые код, ДЗ и файлы удалены. Тест на большой файл с переносами строк добавлен (без исправления он падает).
