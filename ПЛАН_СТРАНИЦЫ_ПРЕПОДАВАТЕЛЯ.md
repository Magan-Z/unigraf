# План: страница «Отправить ДЗ с компьютера» для преподавателей

**Статус (2026-10-20): обдумано и согласовано с владельцем, в работу НЕ взято.** Владелец сначала спросит куратора, нужна ли функция.
Если спрос будет и владелец скажет «делай», работа идёт по этому плану. Решение уже принято по пунктам «Согласовано», пункты
«Предложено, ждёт подтверждения» перед стартом коротко переспросить («да по всем»). Выпуск приложения по этой работе владелец
заранее не разрешал: спросить перед выпуском (разрешение «выпускай» на 0.3.9 и 0.4.0 уже использовано).

## Зачем
Преподаватели хранят лекции на флешках и открывают их на компьютерах в аудиториях. Чтобы отправить файл студентам сейчас,
его нужно сначала перекинуть на телефон с режимом преподавателя и отправить оттуда: долго. Компьютеры в аудиториях чужие, поэтому
нельзя оставлять там вход, а код преподавателя одноразовый и вводить его каждый раз нельзя.

## Идея
Отдельная лёгкая страница на сайте (`https://magan-z.github.io/unigraf/teacher/`, преподаватель добавляет её в закладки).
Преподаватель открывает её на компьютере, входит по QR-коду с телефона, заполняет задание, нажимает «Отправить»: задание уходит
студентам под его именем, и вход на компьютере **сразу закрывается** (на сервере).

## Согласовано владельцем
1. Отдельная лёгкая страница, не вся веб-версия. Адрес `…/unigraf/teacher/`.
2. Вход через QR-код с телефона, на котором уже включён режим преподавателя (телефон есть у каждого преподавателя).
3. Ничего не запоминается на чужом компьютере. После **успешной** отправки сервер сразу закрывает вход. При неудачной отправке
   (нет сети, слишком большой файл) вход остаётся, чтобы можно было повторить. Запасной таймер: около 5 минут без движения
   мыши и нажатий клавиш (загрузка файла считается активностью), жёсткий предел сессии около 3 часов.
4. Файлы до 25 МБ каждый (до 5 файлов), хранение в Supabase Storage вместо базы.
5. На странице **нет** списка отправленного, изменения и удаления: ошибку исправляют с телефона (приложение это уже умеет: изменить
   текст, срок, группы, удалить). Если нужно заменить файл: удалить задание и отправить заново с компьютера (новый вход по QR).
6. **Не делать** кнопку «Отправить ещё одно» / оставаться после отправки (решение владельца: преподаватель отправляет одно
   задание после своей пары; один предмет у нескольких групп отправляется одним действием).

## Предложено, ждёт подтверждения (переспросить перед стартом)
- Хранение: Supabase Storage, **публичное чтение** со случайными (UUID) именами файлов; ссылку выдаёт функция сервера, она же
  считает трафик; загрузку разрешает RLS-политика по короткому «билету»; очистку делает `pg_cron` + `pg_net` (удаление объектов
  политикой для строк в таблице-корзине). Всё на SQL, без Edge Functions. Запасные варианты: закрытый бакет и короткие подписанные
  ссылки через Edge Function (строже защита трафика, сложнее); либо файлы в базе кусками по 4 МБ (без Storage, но общий предел 500 МБ).
- Запасной вход текстовым кодом (8 знаков) рядом с QR: для веб-версии на iPhone и если камера не работает.
- Подтверждение входа по QR вводом 4-значного числа с экрана компьютера (защита от QRLjacking: нельзя заставить преподавателя
  отсканировать чужой QR, присланный картинкой). При вводе текстового кода число не нужно.
- Лимиты трафика: месячный потолок 4,5 ГБ на проект вместо суточных 160 МБ (бесплатный Supabase: около 5 ГБ скачивания в месяц,
  иногда до 10 ГБ с кэшем; хранилище 1 ГБ), квота на преподавателя 150 МБ живых файлов, понятное сообщение «лимит исчерпан»,
  подсказка «или дайте ссылку на облако» для файлов больше 10 МБ.
- Загрузка до 25 МБ также из приложения на телефоне преподавателя (сейчас 8 МБ), тот же путь загрузки.
- Порядок выпуска: сначала приложение (0.5.0), через несколько дней, когда студенты обновятся, открыть страницу (старые версии
  приложения не умеют скачивать файлы из Storage: у них будет ошибка).

## Что будет на странице
Вход: QR + число + текстовый код, таймер 3 минуты с автообновлением; после входа «Вы вошли как …». Форма: предмет (по расписанию
преподавателя), группы с «выбрать все», подгруппы, срок, вид (лекция/практика), текст до 2000 знаков, файлы (перетаскивание,
прогресс по каждому, запрещены `.exe .apk .bat .msi .scr .js` и подобные). Экран «Отправлено». «Выйти». Работает и на телефоне.
Все ошибки по-русски (по образцу `SharedApiException.message`). Ничего не хранится после закрытия вкладки (максимум
`sessionStorage`, не `localStorage`; лучше только память).

## Устройство (серверная часть, «Часть 10» `data/supabase/setup.sql`)
- Таблицы: `web_pairs` (запрос входа: id, хеш секрета браузера, 4-значное число, текстовый код, статус, ссылка на строку кода
  преподавателя, срок жизни 3 минуты) и `web_sessions` (хеш токена сессии, строка кода преподавателя, создана, последнее действие,
  срок). Внешний ключ на `teacher_codes` с каскадом: отзыв кода убивает сессии. Не больше 2 сессий на преподавателя.
- Функции (security definer, anon): `web_pair_start()`, `web_pair_poll(id, secret)` (отдаёт токен один раз), `web_pair_approve(
  teacher_token, pair_id, число)` (вызывает приложение), `web_sessions_list/revoke(teacher_token)`, `web_session_end(token)`.
- `teacher_row(p_token)` научить принимать и токен веб-сессии (проверка срока и бездействия, обновление «последнего действия»):
  тогда без переписывания работают `put_teacher_homework`, `get_teacher_homework`, `check_teacher` с теми же лимитами
  (30 отправок в час, свои группы, подпись ставит сервер). `put_teacher_homework` для веб-сессии в конце транзакции закрывает
  сессию.
- Защита: ограничения на число запросов входа и неверных чисел/кодов (по образцу `code_attempts`), общий потолок «ожидающих» запросов.
- Файлы: бакет (например `homework`, лимит 25 МБ), RLS-политика INSERT для anon только по действующему билету (`<билет>/<uuid>`),
  RPC выдачи билета, RPC `register_teacher_file` (проверяет, что объект в `storage.objects` есть и размер ≤ 25 МБ, пишет строку
  `group_files` с `storage_path`, данные в базе пустые), `get_group_file` для таких файлов возвращает URL вместо base64 (и считает
  трафик), очистка (`purge_expired_homework` + корзина + `pg_net`), счётчики трафика.
- Важно: прямое удаление строк `storage.objects` в SQL оставляет файл в хранилище; удалять нужно через API Storage (`pg_net`
  с политикой DELETE для объектов из корзины, либо Edge Function).
- Факты из документации Supabase (проверены 2026-10-20): публичный бакет разрешает анонимам только скачивание, загрузка всегда
  требует RLS-политики INSERT на `storage.objects`; бесплатный план: хранилище 1 ГБ, трафик 5 ГБ без кэша + 5 ГБ с кэшем (общий
  на базу, хранилище и функции), при превышении не списание, а уведомление и льготный период. `pg_cron` уже включён
  (задание `unigraf-purge-expired-homework`), `pg_net` доступен.

## Страница (`data/web/teacher/`)
Самостоятельный HTML/JS без внешних CDN (QR рисует маленькая библиотека, лежащая в репозитории). Перенос в JS правила сопоставления
имени «фамилия + инициалы» (как `same_teacher` в `data/tools/teacher_codes_sql.py` и `lib/domain/search.dart`) с тестами,
подбор предметов из `index.json` и `groups/*.json` на сайте (только группы из сессии). Публикуется вместе с сайтом
(`data/**` запускает публикацию).

## Нюансы, которые нельзя забыть
- Студенты узнают о задании не мгновенно: при открытии приложения или фоновой проверке раз в несколько часов (push-уведомлений нет).
- Лекция 25 МБ для группы из 25 человек = 625 МБ трафика: бесплатного лимита хватит примерно на 8–15 крупных рассылок в месяц.
  Нужны счётчики и понятные сообщения.
- Старые версии приложения не скачают файлы из Storage: поэтому порядок «сначала приложение, потом страница».
- Проверять на настоящем преподавателе-тесте (тестовый код на фиктивную группу, потом всё удалить), в Chrome на компьютере и в
  мобильном режиме, с реальным QR между эмулятором и браузером. Тестовые записи не оставлять (счётчик пользователей: ходить с
  `?nocount`; тестовые коды и группы вроде `zz-test-…` удалять).
- Выпуск и миграции на живую базу: по слову владельца; миграции делать обратно совместимыми.
- Документ для замдекана (`Для_замдекана/`) после выпуска обновить абзацем про вход с компьютера.
- Перед стартом сверить факты с кодом (версии, лимиты, текущие функции `put_teacher_homework`, `get_group_file`), план может устареть.
