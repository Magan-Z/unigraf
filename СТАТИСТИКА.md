# Счётчик пользователей UniGraf

Анонимный: раз в сутки приложение (Android и веб-версия) присылает серверу три значения: **случайный номер установки**
(32 знака, создаётся при первом запуске и лежит только в настройках телефона), **платформу** (android / web / ios) и **версию**.
Имени, группы, расписания, ДЗ и адреса устройства в запросе нет. Запрос весит около 90 байт, уходит в фоне через 4 секунды
после запуска и не чаще раза в сутки; любая ошибка молча игнорируется.

Что считается: сколько **разных установок открыли приложение** за день / 7 / 30 дней. Один человек с двумя телефонами — две установки,
переустановка даёт новый номер. Поэтому это оценка числа пользователей, а не точный список людей.

## Как смотреть цифры

Supabase → проект → SQL Editor → вставить запрос → Run (или попросить агента: «покажи статистику»).

```sql
select * from public.usage_summary;    -- сегодня / за 7 дней / за 30 дней / всего установок
select * from public.usage_by_day limit 30;   -- по дням и платформам
select * from public.usage_by_version; -- какие версии у людей (за 7 дней)
```

## Устройство и защита

- Таблица `usage_ping` и сводки закрыты для приложения: оно может только отправить отметку (`ping_usage`), прочитать ничего нельзя.
- Сервер принимает только правильный формат (номер из 32 шестнадцатеричных знаков, платформа из списка, версия до 16 знаков).
- Не больше 20 000 записей за день (защита от накрутки и от переполнения бесплатной базы); записи старше 400 дней стираются.
- Код: `app/lib/usage_ping.dart`, серверная часть: часть 7 в `data/supabase/setup.sql`, тесты: `app/test/usage_ping_test.dart`.
- Версия вшивается при сборке релиза (`--dart-define=APP_VERSION`); у веб-версии и локальных сборок версия пустая.
- Проверки разработчика в браузере: откройте веб-версию с `?nocount` в адресе (например, `.../app/?nocount`), тогда отметка не отправляется и тестовые установки не завышают счётчик. Удалять записи из таблицы после проверок больше не нужно.
