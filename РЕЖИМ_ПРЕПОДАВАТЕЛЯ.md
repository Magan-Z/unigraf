# Режим «Я преподаватель» и ДЗ от преподавателя

Документ с проектом решения (составлен 2026-10-14 до начала кода) и итогами. Задача от владельца (по просьбе куратора): отдельный режим преподавателя и возможность отправлять ДЗ студентам от имени преподавателя.

## Что получает преподаватель

1. **Расписание без регистрации.** При первом запуске (или в «Настройки → Профиль») выбирает «Я преподаватель» и находит себя в списке. Дальше «Сегодня», «Неделя», виджеты и напоминания показывают его пары по всем группам. Лекции для нескольких групп склеиваются в одну карточку; на месте фамилии преподавателя на карточке написаны группы («1 БИ-24, 2 БИ-24»; если пара только для подгруппы — «БИ-26-1»; физкультура — с пометкой юноши/девушки).
2. **Отправка ДЗ студентам.** Нужен одноразовый **код преподавателя** (его выдаёт владелец приложения, как коды старост). Без кода режим работает как «только смотреть расписание».
3. Вкладка «ДЗ» у преподавателя превращается в «Домашка студентам»: список отправленного (с группами, сроком, файлами; изменить / удалить) и кнопка «Отправить ДЗ».

## Что видят студенты

В «ДЗ» появляется третья вкладка **«От преподавателей»** (только если есть что показать), карточки с именем преподавателя и пометкой «от преподавателя»; отметка «сделано» — личная, как у ДЗ старосты. Фоновая проверка присылает уведомление «Преподаватель добавил ДЗ».

## Главные решения (и почему)

| Вопрос | Решение | Почему |
|---|---|---|
| Как показать расписание преподавателя, не переписывая приложение | **Синтетическое «расписание»**: из файлов всех групп собираем одно `GroupSchedule` с парами этого преподавателя, в поле `teacher` кладём группы | Всё, что умеет «Сегодня», «Неделя», виджеты, уведомления, перенос по неделям, считается по `MySchedule`, поэтому работает без изменений. Поиск по институту остаётся прежним |
| Личные правки пар у преподавателя | В версии 1 **нет** (меню пары без «Изменить / Перенести / Отменить», кнопки «Мои правки» нет); правки студента в режиме преподавателя игнорируются | Правки в телефоне не привязаны к группе: без разделения студенческие правки попадали бы на пары преподавателя. Разделение — отдельная миграция базы, сделаем, если понадобится |
| Кто может отправлять ДЗ | Только владелец кода. Код выдаётся **на конкретного преподавателя и на список его групп** (список строится из расписания скриптом) | Любой другой путь (имя без проверки) позволил бы выдать себя за преподавателя. Сервер сам проверяет список групп |
| Имя автора | Берётся **сервером из кода**, не от телефона | Подделать нельзя |
| Совместимость | Новые таблицы/колонки/функции, старые функции не меняются по смыслу. ДЗ преподавателей отдаются отдельным ключом `teacher_homework`, поэтому **старые версии приложения их просто не видят** и ничего не ломается | Нельзя ломать приложение у тех, кто не обновился |
| Преподаватели без полного ФИО | Работаем с инициалами («Абубакаров М.»), справочник (91 ФИО) подмешивается автоматически; когда владелец пришлёт полные ФИО, они попадут в справочник и всё подхватится | Так просил владелец |
| Однофамильцы | Совпадение по фамилии и первой букве имени, как и в поиске (`sameTeacher`) | Единое правило во всём приложении. Риск: два человека «Абубакаров М.» склеятся, пока ФИО не уточнены |

## Сервер (Supabase), миграция `teacher_mode`

- `teacher_codes(code, teacher, groups text[], token, used_at, created_at)`: закрыта для anon, максимум 2 кода на преподавателя.
- `group_homework` + колонки `author` (null = староста) и `batch_id` (одна отправка нескольким группам = одна «пачка»).
- Функции (anon может вызывать, кроме выдачи кодов): `redeem_teacher_code`, `check_teacher`, `put_teacher_homework(token, row)` (row.groups = [{id, subgroup?}], только из своего списка; можно изменить прежнюю пачку; лимит: 300 живых пачек и 30 отправок в час), `delete_teacher_homework(token, batch)`, `get_teacher_homework(token)` (мои пачки), `put_teacher_file`, `owner_issue_teacher_code(name, groups[])` (только владелец).
- `get_group_data` по-прежнему отдаёт `homework` (только старост, `author is null`) и теперь ещё `teacher_homework`.
- `get_group_file` отдаёт файл, если он лежит в этой группе **или** прикреплён к живому ДЗ этой группы (один файл хранится один раз для всех групп пачки); суточные потолки скачивания остаются.
- Все новые таблицы с RLS и без доступа для anon; `search_path` пустой, как у остальных функций.

## Приложение

- **Состояние:** `Settings.role` (`student` / `teacher`), `Settings.teacherName`; профиль студента хранится отдельно и не стирается при переключении. `TeacherSession` (токен, имя, группы) в телефоне, как токен старосты.
- **Новое:** `domain/teacher.dart` (сборка расписания и целей отправки), `domain/teacher_homework.dart`, провайдеры `teacherViewProvider` / `teacherSessionProvider` / `teacherSentProvider`, экраны `features/teacher/…` (вкладка «Домашка студентам», окно отправки, окно кода).
- **Меняется:** `main.dart` (первый запуск), `onboarding_screen.dart` (выбор «Студент / Преподаватель», список преподавателей), `settings_screen.dart` (профиль и раздел «Преподаватель»), `home_shell.dart` (вкладка ДЗ по роли), `homework_screen.dart` (вкладка «От преподавателей»), `day_edits.dart` (меню пары), `app_state.dart` (ветвление по роли; в режиме преподавателя не ходим на сервер за данными группы и не показываем личное ДЗ студента).
- Сеть нужна только для отправки ДЗ и получения чужих ДЗ; расписание работает без неё.

## Как это проверять

Тесты (парсер/приложение/Kotlin) + новые тесты: сборка расписания преподавателя, протокол, экраны (первый запуск преподавателя, «Сегодня» с группами, отправка ДЗ, вкладка у студента, переключение ролей туда-обратно). Сервер: сценарий в откатываемой транзакции (коды, чужие группы, лимиты, изоляция). Вручную: эмулятор, боевая сборка.

## Отправка с компьютера (страница `/teacher/`, ветка `teacher-page`, не выпущено)

Преподаватель открывает страницу на компьютере в аудитории, входит по QR с телефона (Настройки → «Вход на компьютере»: сканировать QR и ввести число с экрана, либо ввести код из 8 знаков) и отправляет одно задание: предмет, группы, срок, текст, до 5 файлов по 15 МБ. После успешной отправки сервер закрывает вход; вход закрывается и через 5 минут без движения мыши и нажатий, и через 3 часа, и при закрытии вкладки. Ничего не сохраняется на компьютере (токен только в памяти вкладки). Изменить или удалить отправленное можно только в приложении.
Устройство: `data/web/teacher/` (`index.html`, `app.js`, `teacher-logic.js`, `qrcode.js` — библиотека без изменений с лицензией, `config.js` — адрес сервера и публичный ключ), сервер — Часть 10 в `data/supabase/setup.sql`, приложение — `app/lib/features/teacher/web_login_screen.dart`. Проверки логики: `node --test data/web_tests/*.test.mjs`. Подробности и порядок выпуска: `ПЛАН_СТРАНИЦЫ_ПРЕПОДАВАТЕЛЯ.md`, журнал: `ХОД_РАБОТ.md`.
